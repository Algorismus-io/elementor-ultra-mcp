## Summary

Implement the schema-drift guard: snapshot the LIVE post-filter `get_props_schema()` for every supported atomic widget + the Style-Schema into committed baselines, and the `test:drift` test that re-fetches them from wp-env, normalizes, and fails on any diff vs the baseline (and asserts the TS pre-filter's hardcoded enum/required expectations match the baseline). This catches Elementor version drift at CI, not at a customer save. The CI job that runs `test:drift` as a required check is wired by WP-F07; this WP owns the TEST + the baselines.

## Interface / Contract

- **`schema-normalize.ts`.** Normalizes a live schema (`14-fixtures-harness.md §5 step 3`): stable key sort; strip volatile fields (labels/descriptions); KEEP prop names, `$$type` keys, enum members, required flags, units. Deterministic output for byte-diffing.
- **`schema-drift.test.ts`.** For every supported NON-Pro atomic widget (the 15 in `files_owned`, SUPPLEMENT §B.2) + the Style-Schema: call `schema.widget`/`schema.styles` (Contract 13 §1.1) against wp-env to fetch the LIVE post-filter `get_props_schema()` (incl. `_cssid`, Pro-injected `display-conditions`, runtime-extended background sub-schema); normalize; diff vs the committed baseline; FAIL on any diff with a per-widget added/removed/changed-props message (`§5 step 5`). Also assert (a) the baseline filename set equals the WP-F03 supported-types constant (no silent coverage gap), and (b) the TS pre-filter's hardcoded enum/required expectations match the baseline (`§5` last line). The Pro `e-form` family leg is gated behind `requires.pro` and snapshotted only on a Pro wp-env (not a committed baseline file here).
- **Baselines** `packages/shared/fixtures/schemas/*.schema.json` — the committed normalized snapshots; the drift job's reference. Generated by `pnpm fixtures:snapshot-schemas` (owned by WP-F06); this WP commits the initial snapshots and owns them thereafter.
- The drift job NEVER auto-updates the baseline (`§5`); regeneration is the manual reviewed `fixtures:snapshot-schemas` whose PR diff is the human gate.

## Dependencies & Inputs

- Upstream: WP-F03 (the pre-filter whose expectations the baseline cross-checks; the schemas/types), WP-F06 (the fixture dir + the `fixtures:snapshot-schemas` script that produces baselines + the loader/wp-env bootstrap). The live fetch uses the `schema.widget`/`schema.styles` tools (TS) backed by the PHP schema controller — feature-detect + skip if not yet present (the drift test can run against the PHP route directly once it exists).
- Contracts: `14-fixtures-harness.md §5/§10/§0`; `13-tool-catalog.md §1.1`; RESEARCH §9.3b/§10.
- Elementor APIs (cited): `get_props_schema()` post-filter (`has-atomic-base.php:310-321`) — FETCH this, not `define_props_schema()`; the schema includes `_cssid` injection; Pro injects `display-conditions`.

## Detailed Requirements

1. **Snapshot every supported NON-Pro atomic widget** (SUPPLEMENT §B.2) + the Style-Schema into `fixtures/schemas/*.schema.json` using `fixtures:snapshot-schemas` against the pinned Elementor 4.1.1 + Pro 4.1.0 wp-env; commit them. The owned set is EXACTLY the 15 non-Pro atomic widgets enumerated in `files_owned` — the 6 core (e-heading, e-paragraph, e-button, e-image, e-div-block, e-flexbox) PLUS e-svg, e-divider, e-youtube, e-self-hosted-video, and the tab family (e-tabs, e-tabs-menu, e-tab, e-tabs-content-area, e-tab-content) — plus `style-schema.json`. The Pro `e-form` family (`e_pro_atomic_form`) is NOT a baseline file here; its drift leg is gated behind `requires.pro` (see Implementation Notes) and snapshotted only on a Pro install — it is intentionally excluded from `files_owned` so the free-only baseline set is complete and provable. (The supported-widget list is sourced from the WP-F03 supported-types constant; if WP-F03 adds an atomic widget, a new baseline file must be added here — the drift test asserts the baseline set equals that constant so coverage cannot silently regress.)
2. **Normalize deterministically** (`§5 step 3`): keep prop names/`$$type`/enums/required/units; drop labels/descriptions; stable sort.
3. **Drift test** fetches live → normalizes → diffs vs baseline → fails on diff with a readable per-widget delta.
4. **Pre-filter cross-check:** assert WP-F03's pre-filter hardcoded enum/required expectations equal the baseline, so a baseline change the pre-filter wasn't updated for ALSO fails (`§5` last line).
5. **`pnpm test:drift`** is the script name (already reserved by F06 `§10`); this WP provides the test it runs. WP-F07 wires it as the required check on PRs touching `packages/shared/schemas/**` or the pre-filter.
6. **Never auto-update baseline** in the test/job; only the manual reviewed `fixtures:snapshot-schemas` regenerates it.
7. **`INDEX.md`** documenting each baseline + how to regenerate intentionally on an Elementor bump.

## Implementation Notes

- The Style-Schema baseline is the largest + most drift-prone (enum-heavy, `style-schema.php:135-426`); ensure normalization keeps all enum members so an enum addition/removal is caught.
- Pro-injected props (`display-conditions`) appear only on a Pro install — snapshot a Pro baseline leg and gate the Pro portion behind `requires.pro` so the free leg's drift test stays green.
- This WP ADDS the baselines + the drift test file; it never edits F06's runner or other QA fixtures (disjoint; Q02 owns `schemas/**` + the drift test).
- The drift message must list added/removed/changed props per widget so a maintainer can either regenerate (intentional bump) or investigate (`§5 step 5`).
